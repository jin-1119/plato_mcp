# plato-mcp 실배포 검증용 테스트 프롬프트 (Render + Smithery)

이 문서는 이슈 [#72](https://github.com/jin-1119/plato_mcp/issues/72) — "fresh
install + 실제 tool call 라이브 검증" — 를 위한 체크리스트입니다. Render에 배포한
서버(`https://<your-service>.onrender.com/mcp`)를 smithery.ai에 등록한 뒤, **개발
환경이 아닌 3가지 실사용 경로**에서 각각 새로 연결해 실제 PLATO 계정으로 도구를
호출해봅니다.

## 준비물

- Smithery에 등록된 서버 주소: `https://smithery.ai/server/<namespace>/plato-mcp`
  (예: `jinyeonggim844/plato-mcp` — 실제 등록한 namespace로 바꾸세요)
- 실제 PLATO 학번/비밀번호 (`.env`의 `PNU_STUDENTS_ID` / `PNU_STUDENTS_PASSWORD`
  와 동일한 테스트 계정) — **이 문서나 채팅 어디에도 비밀번호를 직접 붙여넣지
  마세요.** 각 클라이언트의 커넥터 설정 화면(폼 입력창)에만 입력합니다.
- 세 곳 모두 **새로 연결(fresh install)** 해야 의미가 있습니다 — 이미 로컬
  개발용으로 연결되어 있던 세션을 재사용하지 마세요.

Render 무료 요금제는 15분 무요청 시 잠들기 때문에, 각 섹션의 **첫 호출은 30초~1분
정도 걸릴 수 있습니다** (정상입니다 — 오류가 아님).

## 2. Claude Code 용 테스트

### 연결 방법
로컬 CLI에서 원격 Smithery/Render 서버를 MCP 서버로 등록합니다 (로컬 소스 코드를
쓰는 게 아니라, 배포된 원격 주소를 씁니다):

```bash
claude mcp add --transport http plato-mcp-live \
  "https://<your-service>.onrender.com/mcp?pnu_id=<학번>&pnu_password=<비밀번호>"
```

> `pnu_id`/`pnu_password`를 쿼리 파라미터로 넣기 꺼려지면, Smithery 등록 페이지에
> 나오는 "설치 방법" 탭에 표시되는 실제 연결 문자열(헤더 기반일 수도 있음)을
> 그대로 써도 됩니다 — Smithery가 만들어주는 형식이 최신 기준입니다.

등록 후 `claude mcp list`로 `plato-mcp-live`가 뜨는지 확인하고, 새 Claude Code
세션(새 터미널/새 대화)을 시작합니다.

### 테스트 프롬프트

```
plato-mcp-live 커넥터로 내 강좌 목록 가져와줘.
```

```
그 중 하나 골라서 과제 목록과 마감일 알려줘.
```

```
이번 주 캘린더 일정(list_calendar_events) 확인해줘.
```

```
공지사항 목록(list_notices) 하나 강좌에서 가져와서 최신 글 제목만 보여줘.
```

### 확인 포인트
- Claude Code가 로컬 `src/` 코드가 아니라 **원격 Render 서버**를 호출하고
  있는지 (등록한 이름 `plato-mcp-live` 기준으로 도구가 호출되는지 확인).
- 응답 지연(첫 호출 30초~1분)이 Render 콜드스타트 때문인지, 진짜 오류인지
  구분 — 두 번째 호출부터는 빨라져야 정상.
- 에러 발생 시 `claude mcp get plato-mcp-live`로 설정이 제대로 들어갔는지 확인.

## 3. 제3의 에이전트 (opencode 등) 용 테스트

opencode처럼 MCP 서버를 설정 파일(JSON)로 등록하는 클라이언트 기준입니다.
설정 파일에 아래와 같은 형태로 추가합니다 (opencode의 정확한 설정 파일 경로/키
이름은 버전에 따라 다를 수 있으니, 해당 도구의 MCP 설정 문서에서 "remote /
http / url" 타입 서버 등록 방법을 확인하세요):

```json
{
  "mcpServers": {
    "plato-mcp-live": {
      "type": "remote",
      "url": "https://<your-service>.onrender.com/mcp?pnu_id=<학번>&pnu_password=<비밀번호>"
    }
  }
}
```

등록 후 opencode를 재시작(또는 MCP 서버 목록 새로고침)하고, 새 세션을 엽니다.

### 테스트 프롬프트

```
plato-mcp-live 서버를 통해 내 PLATO 강좌 목록을 가져와줘.
```

```
그 중 하나를 골라 성적(get_grades) 확인해줘.
```

```
Q&A 게시판 목록(list_qna) 가져와서 최근 글 제목 알려줘.
```

### 확인 포인트
- opencode가 이 서버를 도구 목록에 정상적으로 로드했는지 (연결 직후 도구
  개수가 14개로 나오는지 — 안 뜨면 스캔/로드 자체가 실패한 것).
- 첫 호출의 콜드스타트 지연을 타임아웃으로 오해해서 재시도 루프에 빠지지
  않는지 (안 되면 한 번 더 같은 프롬프트 시도).
- 세 클라이언트 중 유일하게 "정식 커넥터 UI"가 아니라 수동 JSON 설정이므로,
  URL에 학번/비밀번호가 그대로 남는다는 점 — 테스트 후 이 설정 파일을 그대로
  커밋하거나 공유하지 않도록 주의.

## 세 곳 모두 실패 시 공통 점검

1. Render 서비스가 실제로 살아있는지: 브라우저로
   `https://<your-service>.onrender.com/mcp` 접속 →
   `{"jsonrpc":"2.0","id":null,"error":{"code":-32600,"message":"Bad Request: Missing session ID"}}`
   가 뜨면 서버는 정상 (세션 없이 접속해서 나는 에러라 오히려 성공 신호).
2. Render 대시보드 → 서비스 → **Logs** 탭에서 실제 요청이 들어왔는지, 어떤
   에러가 났는지 확인.
3. Smithery 리스팅 페이지에서 도구 14개가 여전히 스캔되어 보이는지 재확인
   (서버 URL이 바뀌었거나 재배포로 주소가 달라졌을 수 있음).
4. 여기까지 확인해도 안 풀리면 이슈 [#72](https://github.com/jin-1119/plato_mcp/issues/72)
   에 어느 단계에서 어떤 에러가 났는지 남기세요.
